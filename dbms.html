DBMS Basics: A Complete Beginner's Guide

Learn database management system concepts with simple explanations, examples, tables, SQL queries, keys, relationships and normalization.

1. Introduction to DBMS

DBMS stands for Database Management System. It is software used to create, store, organize, retrieve and manage data in a database.

DBMS provides an organized way to work with large amounts of data. It also provides facilities for security, data consistency, backup and controlled access.

Simple definition: A DBMS is software that helps users store and manage data efficiently.

2. What is a Database?

A database is an organized collection of related data that can be easily accessed, managed and updated.

For example, a college database may store student names, roll numbers, departments, marks and attendance information.

4. Advantages of DBMS

  • Data Organization: Stores data in a structured and organized manner.
  • Data Security: Helps control who can access or modify data.
  • Data Consistency: Helps maintain accurate and consistent data.
  • Data Sharing: Multiple authorized users can access the database.
  • Backup and Recovery: Provides mechanisms for recovering data after failures.
  • Reduced Data Redundancy: Good database design can reduce unnecessary duplicate data.

5. Data Models

A data model describes how data is organized and how different pieces of data are related.

1. Hierarchical Model

Data is organized in a tree-like structure using parent-child relationships.

2. Network Model

Data can have multiple relationships and can be represented as a network of connected records.

3. Relational Model

Data is stored in tables consisting of rows and columns. This is one of the most widely used database models.

4. Object-Oriented Model

Data is represented using objects and classes, similar to object-oriented programming concepts.

6. Tables, Rows and Columns

In a relational database, data is commonly stored in tables.

  • Table: Collection of related data.
  • Row: Represents one record.
  • Column: Represents an attribute or field.

Example

SID SName Dept
101 Arun CSE

Remember: A row represents a record, while a column represents an attribute.

7. Keys in DBMS

Keys are attributes or combinations of attributes used to identify records and establish relationships between tables.

Primary Key

A primary key uniquely identifies each record in a table. It cannot contain duplicate values. 

CREATE TABLE Student (
    SID INT PRIMARY KEY,
    SName VARCHAR(50),
    Dept VARCHAR(30)
);

Foreign Key

A foreign key is an attribute that refers to a key in another table. It is used to establish relationships between tables. 

CREATE TABLE Enrollment (
    SID INT,
    CID INT,
    Marks INT,
    FOREIGN KEY (SID) REFERENCES Student(SID)
);

Candidate Key

A candidate key is an attribute or set of attributes that can uniquely identify a record. One candidate key can be selected as the primary key.

Composite Key

A composite key consists of two or more attributes together used to uniquely identify a record. 

PRIMARY KEY (SID, CID)

Super Key

A super key is any set of one or more attributes that can uniquely identify a record.

9. CRUD Operations

CRUD represents the four basic operations performed on stored data: Create, Read, Update and Delete.

1. Create — INSERT

The INSERT command is used to add a new record to a table. 

INSERT INTO Student
(SID, SName, Dept)
VALUES
(101, 'Arun', 'CSE');

2. Read — SELECT

The SELECT command is used to retrieve data from a table. 

SELECT * FROM Student;

To retrieve selected columns:

SELECT SName, Dept
FROM Student;

To retrieve students from the CSE department:

SELECT *
FROM Student
WHERE Dept = 'CSE';

3. Update — UPDATE

The UPDATE command is used to modify existing records. 

UPDATE Student
SET Dept = 'AI & ML'
WHERE SID = 101;
Important: Always use a suitable WHERE condition when updating specific records.

4. Delete — DELETE

The DELETE command is used to remove records from a table. 

DELETE FROM Student
WHERE SID = 101;
Important: Without a WHERE condition, DELETE can remove all records from the table.

Useful SQL Examples

Create a Table

    SID INT PRIMARY KEY,

Display Students with Marks Greater Than 80

10. Relationships in DBMS

A relationship describes how records in one table are connected with records in another table.

Types of Relationships

  • One-to-One (1:1): One record in one table is related to one record in another table.
  • One-to-Many (1:N): One record can be related to many records.
  • Many-to-Many (M:N): Many records can be related to many records.

11. Normalization

Normalization is the process of organizing data in a database to reduce unnecessary duplication and improve data consistency.

Why Normalization is Used

  • Reduces data redundancy.
  • Improves data consistency.
  • Reduces update problems.
  • Reduces insertion problems.
  • Reduces deletion problems.

First Normal Form (1NF)

A table is in 1NF when each field contains a single atomic value and there are no repeating groups.

Second Normal Form (2NF)

A table is in 2NF when it is in 1NF and every non-key attribute is fully dependent on the whole primary key.

Third Normal Form (3NF)

A table is in 3NF when it is in 2NF and non-key attributes do not depend on other non-key attributes.

Simple idea: Normalization organizes data into appropriate tables so that unnecessary duplication is reduced.

12. Database Transactions

A transaction is a sequence of database operations that is treated as a single logical unit of work.

For example, transferring money between two bank accounts involves more than one database operation. The operations should be completed correctly as one transaction.

Common Transaction Commands

  • COMMIT: Permanently saves the changes made by a transaction.
  • ROLLBACK: Cancels changes made since the appropriate transaction point.
  • SAVEPOINT: Creates a point to which a transaction can later be rolled back. 
START TRANSACTION;

UPDATE Account
SET Balance = Balance - 1000
WHERE AccountID = 101;

UPDATE Account
SET Balance = Balance + 1000
WHERE AccountID = 102;

COMMIT;

13. ACID Properties

ACID properties help ensure reliable database transactions.

Property Meaning
Atomicity A transaction is treated as one unit. It is completed fully or its changes are not applied.
Consistency A transaction should maintain the database according to its defined rules and constraints.
Isolation Concurrent transactions should not improperly interfere with each other.
Durability Once a transaction is successfully committed, its changes should persist despite subsequent failures.
Easy way to remember: A — Atomicity
C — Consistency
I — Isolation
D — Durability
